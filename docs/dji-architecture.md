# DJI 运行架构

LoopWork 只编排和驱动原有 Workflow，OMP 负责模型循环、工具、Skill、原生会话和上下文压缩。

## 固定 Workflow，外部定义

原有流程角色和辅助角色保持固定。启动目录 `.omp/agents/**/*.md` 中的 `name`（或文件名）绑定对应角色；额外文件不会增加流程角色。修改定义后下一次执行读取最新内容，缺失定义直接报错。

专业 Prompt 仅来自外部 Markdown。Harness 附加的是任务范围、权限、状态读取与提交协议，不能由 Prompt 扩大权限。Skill 和 Markdown 模板由 OMP 原生发现及 Agent 引用，不另设内部业务规则库。

模型与思考强度按字段解析：Agent 已启用配置中的显式值 → 外部定义 → 流程默认 → OMP 默认。外部定义中的 tools / skills 仍由 OMP 执行。

## 运行与状态

`start.sh` 启动 Next.js Web/API 和监督宿主。宿主通过监督租约与代次控制一个 Runner，保留任务领取、幂等、资源锁、错误重试、停止和恢复机制。Runner 根据持久化状态和事件派发原有 Pipeline 与 Agent。

每次 Workflow 执行使用独立的 OMP RPC 会话；任务 Chat 继续同一个原生会话。原生 `loopwork` 扩展提供当前 execution 授权的领域命令，服务端验证凭证、阶段、幂等 key 与结果。只有成功提交并通过领域校验才会推进流程。

代码工作目录互斥、Dev/Test 上下文隔离、独立测试计划、验收证据和反馈闭环保持原有约束。

## 单工作目录

一个实例只使用一个启动目录，默认继承调用 `start.sh` 时的目录，也可用 `--workspace` 指定。页面不提供项目管理、项目选择和跨项目筛选。数据库内部的固定命名空间仅用于既有外键、证据与资源锁。

已有任务的状态目录不能改绑其他工作目录。切换仓库应关闭实例并指定独立的 `--data-dir`。

## 文件与数据库

SQLite 保存任务状态、执行状态、关系、配置和文件引用。文档正文、对话、日志与内容快照写入配置的文件目录；文件按内容哈希保存，数据库事务回滚不覆盖已发布版本。原生会话保存在该目录的 sessions 下。

完整备份包含数据根目录（数据库与 payload-key）和所选文件目录。孤立的未引用文件不自动清理。状态 schema 的初始化迁移与领域校验触发器保留，不提供历史数据扫描或导入功能。

## Web 与诊断

保留工作台、需求、定时需求、Pipeline、Agent、运行日志、决策、交付文档和设置界面。事件推送负责正常刷新，丢失事件通过校准恢复。Langfuse 为可选诊断集成，不能影响业务执行结果。

独立经验 Evaluator 默认停用；原有观察和 Memory 界面保留，专业行为仍由外部 Agent / Skill 维护。
