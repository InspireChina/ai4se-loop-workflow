# DJI 运行架构

LoopWork 只编排和驱动原有 Workflow，OMP 负责模型循环、工具、Skill、原生会话和上下文压缩。

## 固定 Workflow，外部定义

原有流程角色和辅助角色保持固定。启动目录直属 `.omp/commands/*.md` 以文件名绑定对应角色；通过原生 `/角色名` 展开，同名 `.cjs` 提供命令链。`.omp/agents` 仅供原生子 Agent 使用，额外文件不会增加流程角色。修改定义后下一次执行读取最新内容，缺失定义直接报错。

专业 Prompt 由 OMP 原生 slash command 从外部 Markdown 展开。工作包注入准确的 Prompt / 脚本路径、角色、Pipeline、链 ID 和首个工具调用；启动前核对原生命令注册与源文件哈希。Harness 附加的是任务范围、权限、状态读取与提交协议，不能由 Prompt 扩大权限。Skill 和 Markdown 模板由 OMP 原生发现及 Agent 引用，不另设内部业务规则库。

模型与思考强度按字段解析：Agent 已启用配置中的显式值 → 外部定义 → 流程默认 → OMP 默认。外部定义中的 tools / skills 仍由 OMP 执行。

## 运行与状态

`start.sh` 启动 Next.js Web/API 和监督宿主。宿主通过监督租约与代次控制一个 Runner，保留任务领取、幂等、资源锁、错误重试、停止和恢复机制。Runner 根据持久化状态和事件派发原有 Pipeline 与 Agent。

每次 Workflow 执行使用独立的 OMP RPC 会话；任务 Chat 继续同一个原生会话。原生 `loopwork` 扩展提供当前 execution 授权的领域命令，服务端验证凭证、阶段、幂等 key 与结果。只有成功提交并通过领域校验才会推进流程。

代码工作目录互斥、Dev/Test 上下文隔离、独立测试计划、验收证据和反馈闭环保持原有约束。

## 命令链与配套脚本

命令链直接加载启动工作目录 `.omp/commands/<agent-id>.cjs`。各文件暴露版本化调度接口与真实可执行函数：阶段描述、初始化、命令执行、校验、结果组装和恢复。原有阶段生成、共享命令、证据及状态操作源码也位于 `.omp/commands/workflow/*.cjs`，可以一起查看和修改。引擎通过 API v1 绑定原有角色和 Pipeline。

页面展示和编辑原始源码，保留阶段可视化及 Chat 辅助；可检查语法、保存外部文件并下载源码。没有命令链 YAML 或数据库配置集。OMP 模型和思考强度的命名配置仍独立保留。代码更改按源码哈希重新加载，模块缓存同步刷新；缺失文件、错误接口或无效阶段直接报错。

原有执行授权、监督、状态流转、Dev/Test 隔离及结果 Schema 继续由 Workflow 管理。角色级校验和结果组装则在同名脚本内，公共实现也公开为源文件；默认算法保留原有阶段门禁。专业步骤、Markdown 模板与规则引用继续使用 `.omp` Skill。

完整接口与文件职责见 [命令脚本接口 v1](./command-script-api.md)。

本仓库提供 `.omp/skills/workflow-commands/SKILL.md` 和独立的 `scripts/workflow/run-check.mjs`：

```sh
node scripts/workflow/run-check.mjs --output /path/to/check-results -- npm test
```

每次调用保留独立的命令参数、工作目录、时间、退出码、标准输出和错误输出；终端输出同步保留。脚本只运行一条显式命令，不维护任务状态或自动重试。通过 OMP Bash 调用时，沿用 Harness 对 Shell 工具的真实 receipt 采集，生成的 JSON 不替代 receipt 或独立验收。临时目录执行结束会清理，长期产物应使用约定的文件夹或提交到领域文件存储。

OMP 原生发现并按需加载工作目录的 Skill；若 Agent 定义配置了 `skills` 名称过滤，应包含 `workflow-commands` 才能使用此 Skill。其他工作目录可自行维护同样的 Skill 和脚本，不会自动复制本仓库内容。

## 单工作目录

一个实例只使用一个启动目录，默认继承调用 `start.sh` 时的目录，也可用 `--workspace` 指定。页面不提供项目管理、项目选择和跨项目筛选。数据库内部的固定命名空间仅用于既有外键、证据与资源锁。

已有任务的状态目录不能改绑其他工作目录。切换仓库应关闭实例并指定独立的 `--data-dir`。

## 文件与数据库

SQLite 保存任务状态、执行状态、关系、资源锁、稳定 ID、时间和文件引用。业务正文、标题、诊断文字、Metadata 与 Runtime 参数均写外部文件，配置的启用状态及绑定关系仍可由 SQL 调度。文档正文、对话、日志与内容快照写入配置的文件目录；文件按内容哈希保存，数据库事务回滚不覆盖已发布版本。原生会话保存在该目录的 sessions 下。

决策树不再按内容列拆散保存。每份命令链草稿和任务级决策树各有一份完整 JSON，节点定义、选项、依赖、推荐、答案、理由和证据都在同一文件。文件位于所选文件目录的 `<taskId>/decisions/<kind>/<scopeId>/<sha256>.json`；决策页面可查看路径、打开和下载当前 JSON。字段使用实际 JSON 对象及数组，不再嵌套转义的 YAML/JSON 字符串。

数据库中的决策节点只保留稳定身份、状态、权限、顺序与文件字段引用；树正文以 JSON 为唯一来源。JSON 中的状态是该版本的记录，调度仍使用数据库状态门禁。变更先写独立文件，再在同一 SQL 事务中发布树引用和各节点引用；回滚不覆盖已发布版本，切换文件目录后旧文件仍可读取。删除节点生成剩余树的新版本，删除末尾节点时清除当前索引，已有文件仍保留。源 JSON 缺失或损坏会显式报错，不从数据库内容兜底。

这些 JSON 是运行产物，不替代 `.omp/commands` 中的可编辑规则源码。请通过原有决策命令和回答入口修改，保证状态、权限、依赖及审计同步；备份或检查文件无需访问数据库正文。

完整备份包含数据根目录（数据库与 payload-key）和所选文件目录。孤立的未引用文件不自动清理。状态 schema 的初始化迁移与领域校验触发器保留，不提供历史数据扫描或导入功能。

## Web 与诊断

保留工作台、需求、定时需求、Pipeline、Agent、运行日志、决策、交付文档和设置界面。事件推送负责正常刷新，丢失事件通过校准恢复。Langfuse 为可选诊断集成，不能影响业务执行结果。

独立经验 Evaluator 默认停用；原有观察和 Memory 界面保留，专业行为仍由外部 Agent / Skill 维护。

纯业务与编排 Command 默认使用 OMP 的内置 read/glob/grep 读取 Skill、Markdown 与项目资料；意图和业务方案节点额外保留 web_search。Workflow 的 loopwork 扩展工具始终可用，产物通过它提交。工具范围在各 Command 原生 frontmatter 中维护，团队可直接修改；研发、复现和独立验证保留项目操作能力。没有新增内部工具权限配置表。

Command 的 tools 通过已有适配器传给 OMP 原生 --tools/--no-tools，只选择内置工具；MCP 仍由 OMP 自身配置管理。线协议探针已分别核对默认、只读与空集合，且确认 Command 正文确实展开。
