# 统一 Work Item 与 Intervention

状态：生产编排已默认使用统一模型；完整迁移验收进行中，尚未发布。

## 目标与权限边界

Work Item 表示工作义务，依赖图决定是否可执行；Intervention 表示需要处置的阻塞。系统辅助、仲裁与人工兜底共用介入记录与执行生命周期，而不是新增专用流程分类。

仲裁复用现有命令，可以有依据地完成 Dev/Test 或回退当前需求的图节点。放宽的是流程处置权限，不是证据真实性：不能改写原测试失败、伪造代码提交或替代其他阶段必需产物。

Review 通过同范围 WORKITEM/INTERVENTION 引用绑定裁决，不要求 Agent 逐字重抄长文本。Harness 从匹配当前节点、不可变完成事件与冻结上下文的权威记录确定性写入报告全文，并明确仲裁不是独立测试通过。缺失引用、跨单元借证据或权威记录变化仍拒绝发布。

## 不变量

- 只派发依赖已完成、无活动介入的 ready 节点；实际激活再次验证。
- 执行绑定确切 item_id、revision、dispatch_epoch；原生代次由 item_id 与 epoch 确定，不由并发通道游标确定。
- 损坏快照不可信；资源清理只能依据真实 owner_execution_id。孤立节点只由不可变保留事件定位。
- 当前派发代次缺失时拒绝恢复和发布，不以冻结 epoch 代替执行代次凭证。
- 暂停、停止和取消保存审计并立即释放自身资源，不覆盖已经发生的错误，也不增加错误次数。
- 请求输入等待不是错误；全部答案保存并显式提交后才 resume。
- 运行信息答案按当前工作项的 Intervention 归属读取。同一节点续跑可以保留答案，新 revision 不得仅因 Agent/key 相同继承旧答案。
- 原生 Recovery 读取不能继续 adoption 或从新写入的旧表行产生介入；历史采纳仅在明确升级边界进行。
- 自动系统辅助至少三次实际未解决尝试再人工兜底；人工显式重置失败额度不伪造辅助次数。
- 需求级介入阻塞整个图。仲裁执行仅排除自己正在处理的全局介入，不能绕过其他介入或暂停/取消。
- 回退保留原完成与失败事实，新建 revision 并重绑下游依赖；旧执行取消，迟到结果不能推进新版本。
- 不变代码/契约/失败的停滞检查跨 revision，反复回退不能清零。
- 契约停滞指纹比较内容，不比较规格记录 ID/版本或 JSON 格式；原样重交规格不视为修复，实质内容变更才重开窗口。
- 原生报告、产物收据、工作项完成、依赖唤醒和结果应用原子提交。
- 普通投影不得从旧 blocked/done/cancelled 标签产生新的控制意图。
- 角色上报失败或交出执行时，只释放自身 owner_execution_id 的资源，不释放同需求其他工作项持有的代码槽。
- 角色结果与报告发布都恢复并校验真实来源的冻结身份；缺失代次、损坏快照或调用者版本不符不能推进节点。

## Recovery 与 Feedback 的事实

原生 Agent Context、修复声明及 Test 成功结果使用 Intervention 和不可变执行收据；RecoveryItem 仅是兼容读模型。回退解除本次编排阻塞，不等于原测试失败已被修复。修复声明只供 Dev 续跑，Test 上下文仍排除 Dev 叙事，声明不能替代完成门禁。

Feedback 冻结批次、逐评论验证和追加计划由图派发；兼容批次/分组 status 可以继续投影，但不能决定派发、报告发布或人工操作权限。报告修订闭环用完成节点产物收据核对报告头。
